Flash Sale Reservation Service — Database Schema

drops
id VARCHAR(255) PRIMARY KEY
sku VARCHAR(255) NOT NULL
totalUnits INT NOT NULL
startedAt TIMESTAMP NOT NULL
endsAt TIMESTAMP NOT NULL
version BIGINT DEFAULT 0
stock
dropId VARCHAR(255) PRIMARY KEY
FOREIGN KEY (dropId) REFERENCES drops(id)
remaining INT NOT NULL
asOf TIMESTAMP NOT NULL
version BIGINT DEFAULT 0
SELECT … FOR UPDATE on stock row for atomic check-and-decrement
reservations
id UUID PRIMARY KEY DEFAULT gen_random_uuid()
dropId VARCHAR(255) NOT NULL, FOREIGN KEY REFERENCES drops(id)
userId VARCHAR(255) NOT NULL
idempotencyKey VARCHAR(255) NOT NULL
quantity INT NOT NULL
state VARCHAR(50) NOT NULL (RESERVED, PAID, EXPIRED, CANCELLED)
createdAt TIMESTAMP NOT NULL
paidAt TIMESTAMP
expiresAt TIMESTAMP NOT NULL
version BIGINT DEFAULT 0
UNIQUE (dropId, userId, idempotencyKey) — prevents duplicate reservations
INDEX (dropId, state) — for finding active/expired reservations
INDEX (createdAt) — for expiry worker queries
Key Design Points:
  • stock table: One row per drop. SELECT … FOR UPDATE locks this row, forcing serialization of all reserve attempts.
  • Idempotency: Unique constraint on (dropId, userId, idempotencyKey) ensures the same request never reserves twice.
  • Atomicity: UPDATE stock SET remaining = remaining - 1 WHERE remaining >= 1 either succeeds (reservation granted) or fails (sold out).
  • Per-user limit: Query sum(quantity) for user+drop, check against max (2 units) before acquiring stock lock.
  • Versioning: @Version fields for optimistic locking in JPA (fallback if needed).
